# Lab 04 — الحماية الأمنية والخصوصية

## نظرة عامة
يبني هذا اللاب طبقات حماية حول **Farah Hospital AI** ضد محاولات Prompt Injection، والطلبات خارج نطاق المستشفى، وتسريب معلومات المرضى أو البيانات السرية.

## الأهداف
- إنشاء System Prompt آمن.
- اكتشاف التعليمات المشبوهة أو الخبيثة.
- تقييد المساعد بخدمات المستشفى المسموحة.
- إخفاء بيانات المريض الحساسة قبل إرسالها للنموذج.
- فحص المخرجات لمنع تسريب المعلومات السرية.
- اختبار الطلبات الطبيعية ومحاولات الهجوم.

## مسار الحماية
يمر الطلب بعدة طبقات:
1. **Input Guard** — فحص رسالة المستخدم.
2. **Prompt Injection Guard** — منع محاولات تجاوز التعليمات.
3. **Scope Guard** — منع الطلبات خارج خدمات المستشفى.
4. **PII Masking** — إخفاء المعرفات وأرقام الهواتف.
5. **Secure Prompt** — تحديد الخدمات المسموحة وقواعد الأمان.
6. **Output Guard** — فحص الرد قبل إظهاره.
7. **Secret Leak Protection** — منع تسريب المعلومات السرية.

## مثال على حماية البيانات
إذا احتوت الرسالة على رقم مريض ورقم جوال، يتم تحويلهما إلى:

- Phone Number → `[PHONE_HIDDEN]`

## اختبار الهجمات
تم اختبار ثلاث محاولات خبيثة تشمل:
- تجاهل التعليمات السابقة.
- محاولة كشف الـSystem Prompt.
- محاولة إظهار الكود السري.

النتائج:
- الهجمات التي تم حجبها: **3 / 3**
- الطلبات الطبيعية التي تم حجبها بالخطأ: **0 / 3**

كما تم اختبار منع تسريب المعلومات من المخرجات بنجاح.

## حالة الأمان النهائية
الضوابط المفعلة:
- Input Guard
- Hospital Scope Guard
- Prompt Injection Guard
- Patient PII Protection
- Secure Prompt
- Output Guard
- Secret Leak Protection

## أهم ما تعلمته
الأمان الأفضل يعتمد على أكثر من طبقة، وليس على الـPrompt وحده.  
يجب فحص المدخلات، تقليل وصول النموذج للبيانات الحساسة، تقييد نطاق العمل، ثم فحص المخرجات قبل عرضها للمستخدم.
