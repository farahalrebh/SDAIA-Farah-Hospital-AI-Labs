# Lab 03B — استخدام الأدوات وضوابط الأمان

## نظرة عامة
يضيف هذا اللاب أدوات يمكن لمساعد **Farah Hospital AI** استخدامها، مثل قراءة سجل المريض، فحص توفر الطبيب، حجز موعد، إرسال تنبيه طارئ، أو تحويل الحالة للطاقم الطبي.

التركيز هنا ليس على توليد النص فقط، بل على تنفيذ الأدوات بشكل آمن.

## الأهداف
- تسجيل الأدوات وتحديد مستوى الخطورة لكل أداة.
- التحقق من اسم الأداة والمدخلات.
- حماية العمليات الحساسة بالتحقق من الصلاحيات.
- طلب تأكيد قبل تنفيذ إجراءات عالية الخطورة.
- تحديد الحد الأقصى لعدد خطوات الـAgent.
- تصعيد الحالات الحرجة إلى موظف بشري.

## الأدوات المستخدمة
النظام يحتوي على خمس أدوات:
- `check_patient_record` — قراءة فقط.
- `check_doctor_availability` — قراءة فقط.
- `book_hospital_appointment` — يسبب تغييرًا في النظام.
- `emergency_alert` — إجراء عالي الخطورة.
- `escalate_to_medical_staff` — ينهي العملية بتحويلها للبشر.

## ضوابط الأمان
الدالة `run_tool()` تتحقق من الطلب قبل التنفيذ، وتمنع:
- الأدوات غير المعروفة.
- الحجز بدون صلاحية.
- المدخلات الخاطئة.
- إرسال تنبيه طارئ بدون تأكيد صريح.

## Tool Loop
الدالة `run_with_tools()` تسمح بتشغيل سلسلة من الأدوات بحد أقصى **6 خطوات**، لمنع الـAgent من الاستمرار بلا نهاية.

### مثال حجز موعد
1. فحص سجل المريض.
2. فحص توفر الطبيب.
3. حجز الموعد.
4. إعادة رسالة نجاح.

### مثال حالة حرجة
1. فحص سجل المريض.
2. إنشاء تنبيه طوارئ بعد التأكيد.
3. تحويل الحالة إلى الطاقم الطبي.

## الاختبارات السلبية
أكد اللاب أن الحالات التالية يتم رفضها بأمان:
- Unknown Tool Attack
- Unauthorized Booking
- Wrong Arguments
- Unconfirmed Emergency

## أهم ما تعلمته
لا يجب إعطاء الـAI Agent صلاحية تنفيذ الأدوات بدون ضوابط.  
التحقق من الصلاحيات، التأكيد، تحديد عدد الخطوات، والتصعيد للبشر عناصر أساسية لبناء Agent آمن.
