# Lab 06 — تحسين التكلفة وزمن الاستجابة

## نظرة عامة
يحسن هذا اللاب أداء **Farah Hospital AI** باستخدام طريقتين رئيسيتين:
- **Caching** لتجنب إعادة معالجة الطلبات المتكررة.
- **Smart Model Routing** لاختيار النموذج القوي فقط عند الحاجة.

## الأهداف
- تقدير تكلفة النموذج اعتمادًا على عدد التوكنات.
- مقارنة نموذج مرتفع التكلفة بنموذج أرخص.
- اكتشاف الطلبات المعقدة أو الطارئة وتوجيهها للنموذج الأقوى.
- حفظ الردود المتكررة في Cache.
- قياس التكلفة والوقت وعدد استدعاءات النموذج.

## النماذج المستخدمة
تمت محاكاة فئتين:
- `flagship` — أعلى تكلفة وأبطأ، لكنه مخصص للحالات المعقدة.
- `cheap` — أقل تكلفة وأسرع للطلبات البسيطة.

الطلبات التي تحتوي على كلمات مثل:
`emergency`, `critical`, `severe`, `urgent`, `chest pain`
يتم توجيهها إلى النموذج القوي.

## بيانات الاختبار
- إجمالي الرسائل: **9**
- الرسائل الفريدة: **5**
- الرسائل المتكررة: **4**

وجود رسائل متكررة يجعل استخدام الـCache مفيدًا.

## استراتيجيات التحسين

### Baseline — بدون Cache وبدون Router
- التكلفة: **1600**
- الوقت: **10.8 ثانية**
- عدد الاستدعاءات: **9**
- Flagship Calls: **9**

### Cache Only
- التكلفة: **890**
- الوقت: **6.0 ثوانٍ**
- عدد الاستدعاءات: **5**
- Cache Hits: **4**

### Router Only
- التكلفة: **608**
- الوقت: **5.2 ثانية**
- عدد الاستدعاءات: **9**
- Flagship Calls: **2**
- Cheap Model Calls: **7**

### Full Optimisation — Cache + Smart Router
- التكلفة: **466**
- الوقت: **3.6 ثانية**
- عدد الاستدعاءات: **5**
- Cache Hits: **4**
- Flagship Calls: **2**
- Cheap Model Calls: **3**

## النتيجة النهائية
مقارنة بالنسخة الأساسية:
- التوفير في التكلفة: **1134 وحدة**
- انخفاض التكلفة: **70.9%**
- الوقت الموفر: **7.2 ثانية**
- انخفاض زمن الاستجابة: **66.7%**

## أهم ما تعلمته
ليس كل طلب يحتاج إلى أقوى وأغلى نموذج، والطلبات المتكررة لا تحتاج دائمًا إلى استدعاء جديد للنموذج.  
الجمع بين الـCaching والـSmart Routing يقلل التكلفة والوقت بشكل واضح مع الاحتفاظ بالنموذج الأقوى للحالات المهمة.
